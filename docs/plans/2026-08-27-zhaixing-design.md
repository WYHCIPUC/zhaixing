## 背景与目标

- **一句话目标**：把微信读书导出的划线/想法，变成一个本地桌面应用——可浏览、可检索、可重逢，跨书关联成星空图谱，最终能织成文章。
- **触发场景**：微信读书里划了几百条线，导出后躺在备忘录里再没打开过；"收藏即遗忘"；不同书里的共鸣无法相遇。
- **触发动作**：粘贴/拖入微信读书导出文本，应用自动解析入库。

## 范围外（YAGNI 边界）

**永不**（确认不做，不留扩展点）：
- SRS 间隔重复、闪卡、打卡、遗忘预警——与"只重逢不记忆"哲学冲突（用户明确"不需要特意去记住"）
- 篡改/改写原始导出文本——原文存档是硬原则

**以后可能**（本期不做，预留扩展点）：
- 多来源解析（Kindle/PDF/OCR）→ 预留：解析器按 `source` 枚举分发，接口按"纯文本输入→结构化输出"设计
- 概念卡词典、那年今日、盲盒拾星 → 预留：数据模型已含时间维度与主题聚合，纯 UI 层增量
- 全局摘星、金句视频、星空网页发布、微信读书自动同步 → 无需预留，均为独立子系统

## 决策日志

| 选项 | 选择 | 理由 | 否决项及原因 |
|---|---|---|---|
| 桌面框架 | Electron | 全 JS 栈（解析/AI/图表/星图）迭代最快，个人工具重感知轻包体 | Tauri：Rust 工具链与前后端桥接成本高，排查问题慢 |
| 存储 | SQLite (better-sqlite3) | FTS5 全文检索 + 关系查询（连线/星云）必需 | 纯 JSON 文件：检索与关联查询做不动；IndexedDB：主进程无法直接用 |
| 向量检索 | SQLite blob + JS 余弦 | 个人规模（万级）毫秒级，零额外依赖 | 外部向量库（milvus 等）：过度设计 |
| 星图渲染 | d3-force + Canvas 2D 自绘 | 星空美学需要逐粒子发光/闪烁控制 | 现成图库（sigma/cytoscape）：视觉定制受限，星空感出不来 |
| AI 接入 | fetch 薄客户端（OpenAI 兼容） | base_url 可配，GLM/DeepSeek/OpenAI 通吃 | openai SDK：锁生态、重；本地模型：个人机跑不动 |
| 复习哲学 | 重逢系（流星日报+时间胶囊） | 用户明确"不需要特意去记住" | SRS/闪卡：列入"永不" |
| 解析策略 | 按用户真实导出样本编写 + 回归用例 | 格式风险是最大不确定性 | 凭通用格式猜测：错一字全盘错 |
| 想法建模 | 独立 `thoughts` 表 | 年轮批注需要一层星多层想法按时间叠放 | highlights.thought 单字段：无法年轮 |

| 维度 | 假设 | 验证方式 | 若破裂的回退 |
|---|---|---|---|
| 外部依赖 | 微信读书导出格式稳定、用户能提供真实样本 | M1 开工前索取 1–2 份样本跑通解析 | 解析预览 UI 逐条修正 + 解析规则容错放宽 |
| 数据规模 | 个人使用 ≤ 5 万条划线 | 导入后统计面板 | 星图升级 WebGL / 列表分页 |
| 第三方契约 | 用户可提供 OpenAI 兼容 API key | 设置页"测试连接" | 未配 key 时全部手动功能可用，AI 功能优雅隐藏 |
| 环境与部署 | better-sqlite3 有匹配 Electron ABI 的 prebuild | 安装即验证 | @electron/rebuild 编译；再不行改用 node:sqlite |
| 用户行为 | Windows 单机使用，无多端同步需求 | 已确认 | 导出 Markdown 即迁移路径（Obsidian 兼容） |
| 并发与时间 | 单进程单用户，无并发写 | 设计如此 | 不适用 |

## 架构与组件

```
src/
├── main/            # Electron 主进程
│   ├── index.ts         # 窗口创建、生命周期
│   ├── db/              # schema + 迁移 + repository（[internal]）
│   ├── parser/weread.ts # 微信读书解析器（[internal]，有回归用例）
│   ├── ai/client.ts     # OpenAI 兼容薄客户端（[internal]）
│   ├── exporters/markdown.ts
│   └── ipc.ts           # IPC handlers（[public] 渲染层唯一依赖面）
├── preload/index.ts     # contextBridge 暴露 window.api
└── renderer/            # React 应用
    └── src/
        ├── views/       # 书架 / 星穹 / 流星 / 织星 / 统计 / 设置
        ├── components/  # 导入向导、星卡、想法年轮…
        └── starfield/   # Canvas 星野引擎（[experimental] 视觉迭代频繁）
```

- 每个单元职责：`db` 做持久化与查询；`parser` 做纯文本→结构化；`ai/client` 做 HTTP+重试；`ipc` 做编排（解析入库、AI 管线、导出）；renderer 只经 `window.api` 通信，不碰 Node。
- 兼容承诺：`window.api`（IPC 面）为 `[public]`，破坏性变更需迁移；`starfield` 为 `[experimental]`。

## 数据流

- **导入**：粘贴文本 → `parser` 解析 → 预览（可修正）→ 确认 → 哈希去重 → 入库 + 原文存档 `import_archives`
- **AI 管线**：选书/选星 → embedding → 聚类成星云（ai 来源）→ 跨书相似对成 `links(suggested)` → 用户逐条确认/忽略
- **重逢**：启动查当日 `capsules` 到期项并入流星日报；无胶囊则从低重访星中挑
- **导出**：查询 → markdown 渲染 → 保存对话框

## 错误处理

- **输入异常**：解析零命中 → 明确报错并保留原文到存档，引导检查格式；部分失败 → 报告"成功 N 条、失败 M 条"
- **依赖故障**：AI 网络失败 → 重试 3 次退避，失败入待处理队列，结果一律落库不丢；未配 key → 隐藏 AI 入口
- **状态冲突**：重复导入 → 内容哈希跳过并报告计数；星云/连线重复建议 → 幂等去重
- **资源耗尽**：星图超载 → 视口裁剪 + 分批绘制；DB 体积 → 不担心（个人规模）
- **数据安全**：每次启动自动备份 `zhaixing.db` → `zhaixing.backup.db`（单份轮换）

## 非功能性约束（NFR）

- **隐私（硬约束）**：数据全部本地；仅 AI 调用按需发送所选文本到用户自己配置的端点
- 性能：启动 < 3s；星图 1000 星 60fps 交互
- i18n：仅中文
- 可访问性：基础键盘可达
- 未列出的（安全审计、可观测性等）默认非约束
